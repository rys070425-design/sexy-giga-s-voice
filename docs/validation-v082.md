# 0.8.2 · 주저하는 대화의 문맥 보존

이번에는 큰 음성 모델을 무조건 넣는 대신, **일반 대화에서 문장을 너무 빨리 끊던 부분**을 고쳤습니다. 첫 초안은 계속 먼저 보여 주고, 짧게 주저하는 구간을 조금 더 이어서 확정 인식합니다. 기본 모델은 Whisper large-v3-turbo / faster-whisper이며 번역은 NLLB-200 distilled 600M CPU int8입니다. 새로 학습한 모델은 아닙니다.

## 실제 바뀐 동작

프로필의 **번역 문맥 → 일반 대화 · 문장 문맥 유지**에서는 짧은 머뭇거림을 즉시 문장 끝으로 처리하지 않습니다. 음성 인식과 번역에 더 긴 구절을 전달합니다. 확정 문장이 이전보다 조금 늦게 나올 수 있지만, 말하는 동안의 초안은 문장이 끝나기를 기다리지 않습니다. 최대 8초 분할과 겹침 처리는 유지합니다.

**게임 대화**의 짧은 호출 확정 간격은 기존과 같습니다. 새로 만드는 **디스코드 · 대화** 기본 프로필은 일반 대화를 사용합니다. 기존에 저장한 프로필을 강제로 바꾸지는 않으므로, 기존 사용자는 일반 대화 문맥을 직접 선택하고 저장한 뒤 자막을 다시 시작하세요.

두 줄 자막, 약 0.8초 간격의 안정적 표시, 기본 배경 진하기 42%, 재생 앱/선택 확장 사이트 이름, Discord 최초 승인 후 통화방 자동 연결, 8개 표시 언어, 원문 비교와 수동 기록 저장은 포함합니다. 기존 [0.8 사용 안내](validation-v080.md)와 [설치 구성요소 정리](validation-v081.md)도 적용됩니다.

## 실제 억양을 전체 흐름으로 다시 검사

같은 RTX 4050 Laptop 6GB PC에서 [Speech Accent Archive](https://accent.gmu.edu/)의 기존 내려받은 읽기 녹음 두 개를 50ms씩 실제 시간으로 공급했습니다. 영어 고정, GPU int8_float16, 확정 beam 5, 일반 대화 문맥, NLLB 번역으로 새 EXE에서 설치된 앱 코드를 검사했습니다. 스피커 재생이나 마이크 사용은 하지 않았습니다.

| 입력 | 0.8.1 확정 인식 WER | 0.8.2 확정 인식 WER |
|---|---:|---:|
| korean1, 43.15초 | 17.39% | **10.14%** |
| spanish1, 33.65초 | 4.35% | **4.35%** |

첫 자료는 같은 69개 기준 단어에서 오류가 12개에서 7개로 줄었습니다. 두 번째 자료는 3개로 같았습니다. 모델 가중치와 인식 정밀도는 같고 일반 대화의 분할 방식이 달라졌습니다. 두 입력 모두 번역 결과를 생성했고 대기열 초과 없이 작업을 정상 종료했습니다. 확정 표시 구간은 각각 11→7개, 7→5개였습니다. 내부 번역 초안 수와 실제 화면 갱신 횟수는 다른 값입니다.

WER는 인식된 영어 단어의 오류율이며 번역 점수가 아닙니다. 대소문자·문장부호를 정리하지만 숫자 표기는 통일하지 않습니다. 인식 오류가 번역으로 이어지거나, 맞게 인식한 내용도 번역 모델이 생략·오역하는 사례는 남았습니다. 녹음 두 개의 개선을 모든 억양이나 실제 통화의 정확도 개선으로 일반화하지 않습니다. 원본 음성이나 전체 읽기 문단·번역 대화는 새 배포 자료에 넣지 않았습니다.

분할 조건을 고를 때 사용하지 않은 새 영어 일상 문장도 Windows SAPI로 만들었습니다. 일반 음성과 **1.25배속 + 250~2300Hz 대역 제한 + 15dB 잡음**을 비교했습니다. 일반 입력 WER는 변경 전/후 모두 0%, 변형 입력은 모두 3.33%였습니다. 이 추가 문장에서는 오류 증가 없이 부정 표현이 유지됐습니다. 작은 자체 시험이며 실제 사람의 모든 불분명한 발음을 재현한 것은 아닙니다.

## 첫 자막 시간과 설치 검사

새 일반 대화 모드에서도 자체 합성 음성을 실제 시간으로 공급하고 첫 Qt offscreen 렌더링 완료까지 다시 측정했습니다. 모델 준비 시간을 제외한 첫 초안 기준이며, 실제 모니터의 물리적 표시 시간이 아닙니다.

| 입력 / 표시 | 0.8.2 GPU 첫 렌더링 |
|---|---:|
| 영어 고정 → 한국어 | 0.969초 |
| 영어 자동 감지 → 한국어 | 1.188초 |
| 한국어 고정 → 한국어 | 0.813초 |
| 한국어 자동 감지 → 한국어 | 1.250초 |
| 영어 1.25배속 → 한국어 | 0.938초 |
| 영어 + 10dB 잡음 → 한국어 | 0.891초 |
| 영어 → 영어 원문 | 0.781초 |

7개 조건 각 1회에서 첫 렌더링이 1.4초 이내였고 화면 변경 결정 간격은 최소 0.812초였습니다. 모든 초안을 그대로 화면에 표시하지 않습니다. 실제 억양 녹음의 첫 표시 결정은 파일 시작부터 각각 2.453초와 1.313초였으며, 앞의 무음도 포함하고 Qt 렌더링 완료와도 다른 지표입니다. 모든 실제 음성의 1.4초 보장은 하지 않습니다. CPU와 GPU의 결과도 구분해야 합니다.

회귀 검사 **94개**를 통과했습니다. 일반 대화의 짧은 주저함 보존·첫 초안 유지·게임 짧은 호출의 기존 간격을 따로 검사했습니다. 실제 0.8.2 EXE로 별도 0.8.1 설치 환경을 업그레이드해 종료 코드 0을 확인했고, 설치된 코드로 GPU 인식·실제 NLLB 번역·7개 화면·최소 창 크기·투명도·저장·중복 실행 복구 검사를 통과했습니다. 기본 의존성은 0.8.1과 같으며 Argos/Torch/Stanza 없이 동작합니다.

일반 대화 모드에서 실제 시간 입력을 120초 이상 공급하는 시작/종료 시험을 3회 반복했습니다. 준비와 마지막 처리까지 총 약 6분 30초였고, 빠른 말·작은 소리·잡음을 섞었습니다. 확정 구간은 회차마다 26개로 총 78개였으며 대기열 초과 없이 네 작업 스레드가 모두 종료했습니다. 종료 후 프로세스 메모리는 654.6 / 658.3 / 664.6MiB였습니다. 짧은 반복 시험의 수치이며 수 시간 통화의 메모리 안정성이나 7시간 연속 실행을 검증한 결과는 아닙니다. 원시 기록은 `docs/evidence/pipeline-soak-v082.json`입니다.

Discord 자동 통화방 조회와 확장의 사이트 이름 처리는 공식 응답/브라우저 API의 모의 검사입니다. 실제 사용자 계정 승인, 실제 통화방 이동과 확장 설치를 대신 완료한 것은 아닙니다. 동시에 말하는 혼합 음성을 사람별로 완벽하게 분리하지는 못합니다.

## 모델 선택에서 제외한 자동 변경

화면을 빠르게 원문/번역으로 교대시키는 표시, 모르는 화자·인식 중 문구의 반복, 같은 원문의 중복 표시는 읽기를 방해해 정리했습니다. 기본 번역에 쓰지 않는 Argos·Torch·Stanza 구성요소도 기본 설치에서 제외했습니다. 같은 PC의 0.8 대비 가상환경 파일 합계는 약 849MiB 줄었으며 모델 파일과 공용 Python은 제외한 값입니다. 기존 사용자 언어 팩을 삭제한 것은 아닙니다.

large-v3와 small도 실제로 비교했습니다. 더 큰 large-v3가 변경 전 스트리밍 억양 시험에서 항상 더 정확하지 않았고, small CPU도 1.4초를 달성하지 못했습니다. 그래서 기본 모델 자동 교체나 자동 하향은 넣지 않았습니다. 결과와 선택 방법은 [모델 비교 안내](model-choice.md)에 기록했습니다. 이 설정들은 필요하면 기존 프로필 화면에서 직접 고를 수 있습니다.

## 설치 후 권장 설정

1. 기존 앱과 설치 프로그램을 닫고 **0.8.2 설치 파일**을 실행합니다. 기존 설치가 없어도 준비할 수 있는 온라인 설치 파일입니다. 최초 인터넷 연결과 수 GB의 여유 공간이 필요합니다.
2. Discord·영상의 실제 재생 **출력 장치**를 고릅니다. 마이크 입력은 받지 않습니다.
3. 주로 영어를 들으면 **음성 언어 / Speech → English**, **표시 언어 / Captions → 원하는 언어**를 선택합니다. 자동 감지는 짧은 발화를 오인하거나 더 느릴 수 있습니다.
4. 일상 통화·영상에는 **일반 대화 · 문장 문맥 유지**를 선택하고 저장한 뒤 **Start**를 누릅니다. GPU 우선을 권장합니다. 게임의 짧은 호출은 게임 대화 모드를 사용할 수 있습니다.
5. 배경 진하기는 프로필에서 15~80%로 조절합니다. 원문을 함께 보고 남아 있는 대화 기록을 **Save**로 수동 저장할 수 있습니다.

Discord 닉네임은 봇 초대 없이 공식 최초 승인이 필요합니다. 이후 현재 통화방 자동 연결을 사용하며, 공식 조회가 허용되지 않으면 수동 링크를 사용할 수 있습니다. 닉네임 연결 없이도 소리 자막은 시작할 수 있습니다. 정확한 Chrome/Edge 사이트 이름은 선택 확장을 한 번 연결해야 합니다. [영어 사용 안내](quickstart-en.md)에 한국어 화면 라벨도 정리했습니다.

기본 자막은 유료 API 없이 PC에서 처리합니다. NLLB는 **CC-BY-NC-4.0 비상업용**으로, 무료 개인 사용에 맞춰 준비했습니다. 상업용 무제한 라이선스는 아닙니다. [모델 출처와 라이선스](third-party.md)를 확인하세요.
