# 0.8.1 · 설치 용량 정리와 연결 코드 표시

0.8의 두 줄 자막·안정적 갱신·투명도·재생 출처·Discord 자동 연결을 유지하면서 새 PC에 불필요한 번역 구성요소를 설치하지 않도록 정리했습니다. [0.8 사용법과 실제 측정 결과](validation-v080.md)를 함께 참고하세요.

## 제거한 것과 이유

기본 번역은 NLLB인데 이전 Argos 번역기의 Torch·Stanza·spaCy 구성요소까지 기본 설치 목록에 남아 있었습니다. 현재 화면에서 제공하는 번역 언어는 공용 NLLB 모델이 지원하므로 새 설치에서는 이 중복 구성요소를 제외했습니다. 기존 사용자가 받은 언어 팩이나 구성요소를 삭제하지는 않습니다. 이전 번역 환경이 있으면 호환 경로를 필요할 때만 불러옵니다.

어디에서도 호출하지 않는 구형 `install_models.py`도 배포에서 제거했습니다. 현재와 다른 Whisper base와 구형 번역 모델을 받는 오래된 준비 도구라서 설치 안내와 실제 모델을 혼동시켰습니다. 설치 프로그램과 소스 실행은 공통으로 `prepare_runtime.py`를 사용합니다.

같은 PC에서 두 설치 환경의 가상환경 파일 크기를 합산하면 0.8은 3,798.7MiB, 새 0.8.1은 2,949.9MiB로 **848.8MiB 감소**했습니다. 모델 가중치와 공용 Python은 제외한 설치 후 파일 크기입니다. 다운로드량이나 모든 PC의 설치 시간 절약을 측정한 수치는 아닙니다.

사이트 이름 확장에 붙여넣는 연결 코드는 앱과 확장 설정에서 가려 표시합니다. 앱의 **연결 코드 복사** 버튼으로 복사하여 확장 설정에 붙여넣으면 됩니다. 스크린샷에 코드가 드러나지 않도록 바꿨으며 연결 방식은 같습니다.

## 새 설치 환경 검증

- 새 가상환경을 실제 0.8.1 EXE로 만들고 구성요소 설치를 마쳐 종료 코드 0과 설치 성공 기록을 확인했습니다. 공개 음성·번역 모델 파일만 미리 준비해 재사용했으며 계정·설정은 복사하지 않았습니다. 동일 번역 자료의 빈 폴더 무인증 다운로드는 0.8 검증에서 별도로 통과했습니다.
- Argos·Torch·Stanza·Transformers가 설치되지 않은 상태에서 자동 회귀 검사 **91개**를 통과했습니다. 공용 모델 복구와 선택적 구형 번역 경로의 오류 처리도 포함합니다.
- 설치된 앱 코드로 실제 GPU 한국어 인식, 실제 NLLB 번역, 영어 4문장 전체 처리와 작업 종료를 확인했습니다. 영어 입력 검사는 게임 문맥을 사용한 기능 검사이며 독립적인 번역 품질 점수는 아닙니다.
- 별도 Qt 검사에서 7개 화면·두 줄 자막·투명도·기록 저장·최소 창 크기·중복 실행/종료 후 복구·Discord 재시도 간격·연결 코드 가림 및 복사 동작을 확인했습니다.

이번 버전은 음성 인식 모델이나 자막 표시 간격을 바꾸지 않았습니다. 0.8의 첫 자막 렌더링 측정값 0.781~1.250초는 같은 PC의 합성 입력 7개 조건에서 얻은 첫 초안 기준이며, 실제 모든 통화의 1.4초 보장은 아닙니다. 실제 Discord 계정 승인과 통화방 이동, 사용자의 Chrome/Edge 확장 설치는 아직 사용자 환경에서 확인해야 합니다.

### CPU 모드는 별도 측정

Intel Core i7-13700H에서 GPU를 끄고 Whisper large-v3-turbo CPU int8 / 인식 4스레드 / NLLB CPU int8로 같은 7개 합성 입력 조건을 실제 시간으로 공급했습니다. CPU의 실제 앱 설정과 같은 1.2초 초안 간격을 적용했고, 모델 준비 이후부터 Qt offscreen 렌더링 완료까지 측정했습니다.

| 입력 / 표시 | CPU 첫 표시 |
|---|---:|
| 영어 고정 → 한국어 | 7.625초 |
| 영어 자동 감지 → 한국어 | 13.656초 |
| 한국어 고정 → 한국어 | 7.391초 |
| 한국어 자동 감지 → 한국어 | 13.438초 |
| 영어 1.25배속 → 한국어 | 7.641초 |
| 영어 + 10dB 잡음 → 한국어 | 7.891초 |
| 영어 → 영어 원문 자막 | 7.391초 |

**이 큰 모델의 CPU 모드는 실시간 대화용 1.4초 목표를 달성하지 못했습니다.** 7개 조건 모두 결과와 정상 작업 종료는 확인했지만, 이 CPU 설정에서는 GPU처럼 빠르게 사용할 수 없습니다. 자동 언어 감지는 고정 언어보다 더 느렸습니다. 현재 PC에서는 NVIDIA GPU 우선과 주 사용 언어 고정을 권장합니다. small CPU를 추가로 비교한 결과는 [모델 비교 안내](model-choice.md)에 따로 기록했습니다. 속도 수치를 맞추려고 기본 인식 모델을 자동으로 낮추거나 긴 문맥을 잘라 정확도를 희생하는 변경은 하지 않았습니다. 원시 측정 기록은 `docs/evidence/readable-latency-v081-cpu.json`입니다. 각 조건 1회이며 모든 PC의 CPU 성능을 대표하지 않습니다.

### 실제 영어 억양 입력 추가 검사

[Speech Accent Archive](https://accent.gmu.edu/)의 기존 내려받은 `korean1`과 `spanish1`을 실제 재생 속도로 50ms씩 새 설치 앱의 전체 인식·NLLB 번역 흐름에 공급했습니다. 소리를 스피커로 재생하거나 마이크를 켜지는 않았습니다. GPU / 영어 고정 / 확정 beam 5 / 일반 번역 문맥을 사용했습니다.

| 자료 | 길이 | 확정 인식 WER | 확정 구간 | 번역된 초안 | 첫 표시 결정 |
|---|---:|---:|---:|---:|---:|
| korean1 | 43.15초 | 17.39% | 11 | 77 | 2.516초 |
| spanish1 | 33.65초 | 4.35% | 7 | 73 | 1.344초 |

WER는 표준 읽기 문단과 인식된 영어 단어를 비교한 오류율이며 번역 점수가 아닙니다. 초안 수는 내부 처리 결과 수로 실제 화면 갱신 횟수가 아닙니다. 첫 표시 결정은 파일 시작부터 자막 표시 여부를 결정한 시각으로, 앞부분의 무음도 포함합니다. 실제 모니터 표시나 앞의 합성 입력 Qt 렌더링 측정과는 다른 지표입니다. 이 실제 녹음 조건에서도 모든 첫 표시가 1.4초 이내였다고 주장할 수 없습니다.

두 입력 모두 대기열 초과 없이 번역 결과를 생성하고 작업을 정상 종료했습니다. 인식 오류율은 이전 0.6 분할 시험과 같았습니다. 잘못 인식된 단어가 번역에 그대로 반영되거나 짧게 끊긴 구절에서 의미가 흐트러지는 결과도 확인했습니다. 이는 실제 억양의 번역까지 정확하다는 검증이 아니며, 기본 모델 교체만으로 어려운 발음을 해결했다는 뜻도 아닙니다. 원문 비교와 주 사용 언어 고정을 권장합니다.

수치 기록은 `docs/evidence/accent-pipeline-v081.json`입니다. 원본 음성·전체 원문·번역 대화는 새 배포 자료에 넣지 않았습니다. 자료 제공처는 Speech Accent Archive / George Mason University이며, 사이트는 CC BY-NC-SA 4.0을 안내합니다. 두 개의 읽기 녹음이 모든 억양·겹친 대화의 성능을 대표하지는 않습니다.

## 설치와 사용

1. 기존 앱과 설치 프로그램을 닫고 0.8.1 설치 파일을 실행합니다. 기존 설치가 없어도 사용할 수 있으며 최초 준비에는 인터넷과 수 GB의 여유 공간이 필요합니다.
2. 재생 출력 장치와 **음성 언어 / Speech**, **표시 언어 / Captions**를 선택하고 **Start**를 누릅니다. 자주 듣는 언어를 고정하면 짧은 말의 언어 감지 오류와 지연을 줄이는 데 도움이 됩니다.
3. 프로필에서 배경 진하기를 조절하고, 원문 표시와 남아 있는 대화 기록의 **Save**를 필요에 맞게 사용하세요. 기본 진하기는 42%입니다.
4. Discord 닉네임은 봇 초대 없이 공식 최초 승인이 필요합니다. 이후 현재 통화방 자동 연결을 사용합니다. 닉네임 연결 없이도 출력 소리 자막은 시작할 수 있습니다.
5. 정확한 웹사이트 이름은 선택적 Chrome/Edge 확장을 한 번 연결해야 합니다. 연결하지 않아도 재생 앱 이름과 자막은 사용할 수 있습니다.
