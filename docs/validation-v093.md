# Universal Voice KR 0.9.3 — 속도를 유지하며 정확도 보완

[Windows 설치 파일](https://raw.githubusercontent.com/rys070425-design/sexy-giga-s-voice/main/dist/UniversalVoiceKR_Setup_v093.exe) · [공유용 설치 ZIP](https://raw.githubusercontent.com/rys070425-design/sexy-giga-s-voice/main/dist/UniversalVoiceKR_v093_Windows_Installer.zip)

기존 앱을 닫고 같은 설치 위치에 업데이트하세요. 첫 설치는 인터넷과 수 GB의 여유 공간이 필요합니다. 별도로 Python을 준비할 필요가 없도록 설치 프로그램이 실행 환경을 준비합니다. 이번 검증은 기존 시험 환경의 실제 업그레이드이며, Python이 전혀 없는 새 PC에서 처음부터 시험한 것은 아닙니다.

## 인식과 번역

- 음성 인식은 **Whisper large-v3-turbo**를 유지합니다. GPU 초안은 기존처럼 약 0.5초 분량부터 준비하고 이후 약 0.4초 간격으로 처리합니다. 화면은 가독성을 위해 약 0.8초 간격으로 갱신합니다. 음성을 모으는 시간과 실제 화면 표시 시간은 다릅니다.
- **일반 대화 · 문장 문맥 유지**에서 강제 분할 길이를 8초에서 **10초**로 늘렸습니다. 기존 침묵 감지와 첫 초안 시점은 유지합니다. 길게 이어지는 말은 더 긴 문맥으로 최종 확인합니다. 게임 대화는 8초를 유지합니다. 긴 연속 발화의 최종 확정은 최대 2초 늦어질 수 있지만 그동안 초안은 계속 표시합니다.
- 영어 번역 전에 `I'll → I will`, `I'm → I am`처럼 뜻이 분명한 일부 축약형을 풉니다. 인식 원문과 기록의 원문은 바꾸지 않습니다. 부정 표현, 뜻이 여러 개인 `'s`, `'d`, 비교에서 문제가 있던 조동사 완료형은 유지합니다. URL과 이메일도 보존합니다.
- 시작 시 번역 모델의 실제 계산까지 예열합니다. 모델 파일만 불러오는 것으로 끝내지 않고, 음성·번역 모델이 준비된 뒤 소리를 수집합니다.
- 문장별 정답을 코드에 덧씌우거나 이전 오인식을 다음 인식에 계속 주입하지 않습니다. 이름·지명·전문 용어는 프로필의 **인식할 이름·용어**에 실제 사용하는 단어만 입력할 수 있습니다.

일반 대화와 자동 언어 감지·한국어 말 숨김을 켠 동일 조건에서, 실제 억양 녹음 두 개(각 69단어)를 비교했습니다.

| 자료 | 기존 8초 | 새 10초 |
| --- | ---: | ---: |
| 한국 억양 영어 | 단어 오류율 10.14% (7개) | 8.70% (6개) |
| 스페인 억양 영어 | 4.35% (3개) | 4.35% (3개) |

읽기 녹음 두 개의 최종 인식 결과이며 실제 모든 대화의 정확도나 번역 점수는 아닙니다. 12초 후보는 다른 녹음의 오류를 늘려 제외했습니다. [인식 비교](evidence/accuracy-comparison-v093.json)

번역은 직접 작성한 기존 24문장과 추가 20문장을 비교했습니다. “걱정을 덜 할수록 더 잘 잔다”의 방향이 반대로 번역되던 예와 “도착하면 내가 전화하겠다”가 명령처럼 표현되던 예를 개선했습니다. 여전히 주어 생략, 속어, 부정·가정 표현에 오류가 남습니다. 특히 `I didn't say he stole it.`에서 훔친 주체를 잘못 옮기는 기존 오류는 해결되지 않았습니다. 새 모델로 전면 교체하거나 재학습한 업데이트는 아닙니다. [문장별 번역 비교](evidence/translation-input-v093.json)

## 목소리로 닉네임 보조 확인

**프로필과 자막 → 목소리로 Discord 닉네임 보조 확인**이 기본으로 켜져 있습니다. 설정을 저장한 후 자막을 다시 시작하면 적용됩니다.

1. 기존처럼 공식 Discord 연결을 승인합니다. 봇을 통화방에 초대할 필요는 없습니다.
2. 현재 통화방에서 **두 명 이상**이 각자 혼자 말하는 충분한 구간이 두 번 이상 있어야 목소리와 닉네임을 연결할 수 있습니다. 표시가 겹치거나 출처가 불확실한 구간에서는 학습하지 않습니다.
3. 이후 Discord 출처는 확인됐지만 말하기 표시에서 이름을 얻지 못한 긴 구간에 한해 목소리로 보완합니다. 전체 구간과 앞·뒤 절반의 판정이 일치하고 다른 등록 목소리와 충분히 차이 날 때만 **닉네임: 내용**을 표시합니다. 짧거나 불확실하면 보완하지 않습니다.

모델은 **3D-Speaker CAM++ zh/en advanced ONNX**, 약 28 MB, CPU 한 스레드입니다. 별도의 작업자로 처리하고 번역 측에서 계산 완료를 기다리지 않습니다. 결과가 제때 도착하지 않아도 자막을 먼저 표시합니다. 다운로드는 설치 중에만 하며 파일 크기와 고정 SHA-256을 확인합니다.

목소리 특징과 작업용 음성은 현재 실행의 메모리에만 두고 파일로 저장하거나 외부로 전송하지 않습니다. 통화방 변경·연결 중지·자막 재시작 때 이전 연결 정보를 폐기합니다. 통화방 변경 전 수집된 음성이 새 통화방의 이름으로 학습되지 않도록 세대 번호를 확인합니다. 화면 기록은 기존처럼 명시적으로 저장할 때만 텍스트로 저장합니다.

사람의 실명이나 처음 듣는 목소리의 Discord 계정을 알아내는 기능은 아닙니다. Discord 말하기 표시의 보조 기능이며, 연결 없이 닉네임을 알아내거나 동시에 섞인 두 음성을 각각 분리하지 않습니다. 계속 겹치면 기존처럼 참여 닉네임을 함께 표시합니다. YouTube나 불명확한 재생 출처에는 Discord 이름을 붙이지 않습니다.

실제 녹음 두 사람을 각각 8초씩 등록하고 다른 구간의 깨끗한 음성·15 dB 잡음 음성 8조건에서 **5회 이름 보완, 3회 보류, 잘못된 이름 0회**였습니다. 미등록 합성 목소리 두 개도 보류했습니다. 작은 비교 시험이며 목소리가 비슷한 많은 사람·다른 언어·실제 Discord 통화 전체에 대한 정확도 보장은 아닙니다. [화자 시험](evidence/voice-identity-v093.json)

실제 CAM++와 NLLB를 함께 실행하여 이름이 번역 결과와 두 줄 Qt 자막으로 이어지는 것도 확인했습니다. 이 시험의 발언 표시와 닉네임은 제어된 조건이며 실제 사용자 통화 시험은 아닙니다. [화면 연결 시험](evidence/voice-caption-v093.json)

## 속도와 설치 검증

측정 환경은 RTX 4050 Laptop GPU / RAM 16 GB / Windows, 모델 예열 후 직접 만든 합성 음성을 실제 시간으로 공급하고 Qt 화면 그리기까지 확인한 조건입니다. 첫 화면에 나타나는 초안 기준이며 최종 확정 시간과 다릅니다. 실제 모든 기기·발음·통화에서 1.4초 이내를 보장하지 않습니다. CPU만 사용하는 기기는 더 느릴 수 있습니다.

최종 측정과 반복 실행 결과는 다음 증거에 기록합니다.

126개 회귀 검사와 실제 최종 EXE 설치, 설치된 앱 소스 30파일의 일치, GPU 인식·번역·7개 화면, 설치 창 25개 언어와 로그 창 30회 닫기·다시 열기를 확인했습니다. [설치·구성 확인](evidence/release-checks-v093.json)

최종 설치본의 3초 입력 시험은 첫 외국어 자막 **1.156~1.390초**, 긴 입력 전체 시험은 **1.203~1.516초**였습니다. 같은 언어의 두 조건은 자막 0회였습니다. 짧은 입력의 빠른 영어는 1.172초, 잡음 영어는 1.157초였습니다. 긴 입력의 일부 조건은 1.4초 목표를 넘었으므로, 모든 상황에서 1.4초 이내라고 안내하지 않습니다. 음성·번역 모델 준비 후의 수치이며 첫 실행 모델 다운로드 시간은 포함하지 않습니다.

## 비교 후 제외한 것

- Whisper large-v3 자동 교체: 같은 자동 감지 조건에서 한 영어 억양 녹음을 한국어로 잘못 감지해 많이 숨겼고, 고정 영어에서도 Turbo보다 결과가 나빴습니다.
- 더 큰 탐색 폭·float16 정밀도: 시험한 두 읽기 녹음의 오류 수는 같았고 연산만 늘었습니다. 초안 탐색 폭도 새 합성 24조건에서 개선이 없어 유지했습니다.
- NLLB 1.3B: 뜻 오류가 해결되지 않았고 기존 600M보다 느렸습니다.
- OPUS 영어→한국어 전용 후보: 단어 사전 연결을 수정해 정상 비교했지만, 일부 문장은 개선되는 대신 속어나 복문에서 뜻이 바뀌었습니다. 두 모델 점수로 고르는 후보도 이를 해결하지 못해 추가하지 않았습니다.
- 첫 WeSpeaker 화자 후보: 실제 두 사람의 목소리 점수가 겹쳐 이름을 잘못 붙일 위험이 있어 제외했습니다.
- 과거 대화·목소리 프로필 자동 저장, 유료 API 자동 호출, 자막마다 추가 상태 문구는 넣지 않았습니다.
